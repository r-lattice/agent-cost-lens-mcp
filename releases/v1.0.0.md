# Agent Cost Lens v1.0.0 — the version that launched

*Live at [lens.r-lattice.com](https://lens.r-lattice.com) · 2026-07-18*

Agent Cost Lens answers one question about your Claude Code / Anthropic API
usage: **what did it cost, and how much of that was avoidable?**

## What it does

- **Sweeps locally.** The MCP client (or `lens.py`) reads your Claude Code
  transcripts or your app's API logs on your machine.
- **Scrubs locally.** Repo and session names become salted pseudonyms before
  anything leaves. Prompt text and code are never collected — the wire format
  has no field for them. Run `preview_upload` to audit exactly what would be
  sent before anything is.
- **Analyzes hosted (or fully local).** Spend by model, day, and source; your
  real cache-hit rate; and what a proper caching setup would recover.

## The honesty rules (enforced by tests, not policy)

- Every recovery estimate is labeled **simulated** and **up to** — the
  simulator was validated against measured Claude Code reality before its
  number was ever shown, and the calibration ratio is locked by a test.
- The platform's own cache savings are never claimed as the tool's lift.
- Transcript records are deduplicated by message ID — the naive sum overstates
  costs ~3.7×; the lens doesn't.

## Under the hood

- Hosted analyzer on Cloud Run: hash-only API keys, flag-flip revocation,
  strict wire validation, per-key rate limiting. Events die with the request;
  only per-(key, source, day) aggregates persist.
- Billing via Stripe Payment Link ($29/mo): shown-once key claim,
  signature-checked auto-revoke webhook. Billing is never load-bearing —
  analysis works even if billing is down.
- The MCP client ships as a snapshot with a byte-parity test against the
  engine's collection modules. The engine stays behind auth.
