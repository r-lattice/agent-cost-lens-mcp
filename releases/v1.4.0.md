# Agent Cost Lens v1.4.0 — the wire stops carrying what it never needed

*2026-07-30*

Client update: `pip install --upgrade agent-cost-lens-mcp` (1.2.0). Worth doing —
two of the four changes below are client-side, and a running MCP server keeps the
old code until you restart it.

## Upstream message ids no longer leave your machine

Every record carried its `response.id` — the identifier Anthropic assigned to
that API call — verbatim. It was the one field on the wire that was not already
a local pseudonym, while your source and session names had been hashed since the
beginning.

It is now tagged the same way they are. Nothing downstream loses anything: the
id was only ever used to recognize a record it had already seen, and a stable
tag does that just as well. It simply stops travelling.

If you want to confirm rather than take our word for it, `preview_upload` shows
you the exact records that would be sent. Ids now read `m-…` rather than
`msg_…`.

## A record costs 32% fewer bytes

Two things were being spelled out on every single record and thrown away on
arrival: a timestamp with a `T00:00:00Z` the reader immediately trimmed off,
and the server-tool counters written as zeros even when nothing used a tool.
Both are gone. Measured on 9,548 real records: 403 bytes each became 272.

This is still `apilog-v1`. The reader already accepted both forms, so an older
server reads the newer records without noticing, and you can update the client
and the server in either order.

## Size refusals now say how to fix the problem

If you asked about more history than one request could carry, the answer named
the limit and stopped there — which reads as a broken server rather than as
"ask for less". Both size refusals now tell you to narrow the window with
`--since` / `--until` and repeat for earlier dates.

## The fix advice shows up on the default path

The advice layer — the part that names the specific caching change and what it
would have recovered — only appeared when you passed `--apilog`. A plain run
over your local transcripts, which is how most people use it, computed the
advice and then said nothing about it. It now shows, matching what the hosted
analyzer has always returned.
